# Architectural and scientific decisions

Changes to any row require team agreement; add a new row rather than editing history.

| date | decision | reason | alternatives |
|------|----------|--------|--------------|
| 2026-10-24 | All resampling runs inside `imblearn.pipeline.Pipeline`, only during `fit`, after the train/test split | Resampling before splitting or outside CV folds leaks synthetic/duplicated minority points into validation data and inflates scores | Resample the full dataset up front (leaky); manual per-fold resampling (error-prone) |
| 2026-10-24 | Primary metric is average precision (PR-AUC) | With ~0.17% positives, accuracy and ROC-AUC are dominated by the majority class; PR-AUC reflects performance on the fraud class | Accuracy; ROC-AUC; F1 at a fixed threshold |
| 2026-10-24 | 70/30 stratified train/test split (`test_size: 0.30`, seed from config) | Keeps enough fraud cases (~150) in the test set for stable estimates while preserving class ratio | Time-based split; 80/20 split; nested CV only |
| 2026-10-24 | Raw `Time` excluded from model features | It is seconds since the first transaction in a 2-day window, so it encodes collection order rather than a generalisable signal | Keep raw `Time`; derive hour-of-day (optional side test only, `use_hour_feature`) |
| 2026-10-24 | Outliers are kept | Fraud cases are often extreme values; removing outliers would remove signal and change the class distribution | IQR / z-score outlier removal |
| 2026-10-24 | `RobustScaler` for scaling, fitted inside the pipeline | `Amount` is heavy-tailed; median/IQR scaling is less sensitive to extreme values than mean/std | `StandardScaler`; `MinMaxScaler`; no scaling |
| 2026-10-24 | Shared ratio grid and equal tuning budget for every technique | A fair comparison requires that no technique gets more search effort or a better-tuned ratio range | Per-technique grids; untuned defaults |
| 2026-10-24 | Test set evaluated exactly once, by `scripts/evaluate_test.py` | Any repeated use of the test set for tuning, thresholds or model choice biases the final estimate | Hold-out validation reused as test; repeated test peeking |
| 2026-10-24 | Models: logistic regression, random forest, LightGBM | Covers a linear model, a bagged tree ensemble and a boosted tree ensemble, which respond differently to resampling and class weights | Add SVM / neural networks (cost, limited added insight); single model only |
| 2026-10-24 | Contract 1.1: `EdaSummary` gains optional `imbalance_ratio`, `class_counts_dedup`, `amount_summary` (raw and log1p, with skewness), `time_span_hours`, `effect_sizes` (Cohen's d, sorted by abs(d)), `feature_histograms` (20 shared bins, per-class fractions) and `hour_of_day` (with the midnight assumption stated); `training_counts` defaults to `[]` | Prompt 04 needs these facts for the report and dashboard; EDA cannot fill `training_counts` because it needs tuned ratios. Purely additive, so 1.0 files still validate | Keep 1.0 and write extras to a separate uncontracted file; rename/replace KS with Cohen's d (breaking) |
| 2026-10-24 | Preprocessor output columns are `V1..V28, log1p_Amount` (29); with `use_hour_feature`, raw `Time` is replaced by `hour_sin, hour_cos` (31). Each branch starts with a median imputer; the hour columns are not scaled | `log1p_` makes the transform visible in coefficients and explanations; sin/cos already lie in [-1, 1]. The hour variant has 31 columns (28 + 1 + 2), not 30 | Keep the name `Amount`; a single hour column (loses the 23:00/00:00 adjacency); scale sin/cos too |
| 2026-10-24 | A ratio is only used if it is `> base_ratio x 1.05` (base = training frauds / legit); dropped ratios are logged and recorded in `resampling_audit.json`. The same filter applies to every technique, including F | imblearn rejects targets at or below the current ratio; the 5% margin covers CV folds whose fraud share is slightly higher. On the real data (base 0.00167) nothing is dropped; on the synthetic sample (base 0.015) 0.005 and 0.01 are | Clip ratios to the base; per-technique filtering |
| 2026-10-24 | Technique F's weight is `{0: 1, 1: r / base_ratio}` (`class_weight`, logreg / random forest; plus `"balanced"`) or `scale_pos_weight = r / base_ratio` (LightGBM), passed via `technique_params={"fraud_weight": w}`; `model_params` may not set the class weight for any technique | sklearn's `class_weight` takes a dict or `"balanced"`, not a bare float; keeping the weight inside technique F stops it leaking into other techniques' cells | Bare float weights (rejected by sklearn); weighting the legit class instead |
| 2026-10-24 | Contract 1.2: `ResamplingAudit` gains optional `base_ratio`, `dropped_ratios`; `ResamplingAuditEntry` gains optional `smote_ratio`, `fraud_weight`, `fraud_unique_after`, `fraud_duplicates_after`. The audit is written per CV training fold of the training split (fits the existing per-fold shape) | Prompt 06 asks for unique / duplicate fraud counts and a per-ratio audit; E needs both a and b. Purely additive, so 1.1 files still validate | A second, uncontracted audit file; replace the per-fold shape with a per-ratio one (breaking) |
| 2026-10-24 | Experiment runner (Prompt 08): per cell, `RandomizedSearchCV(n_iter = min(tuning budget, space size))` on `StratifiedKFold(cv_folds, shuffle, seed)`, OOF thresholds on the same folds, then `RepeatedStratifiedKFold(cv_folds, cv_repeats, seed)` fold scores. Each fold row carries `fold_id` (hash of its validation row labels); `merge_results` refuses cells whose seed, mode, training-data hash or fold ids differ. Models fit with `parallel.model_n_jobs` (-1) while search / CV fit one candidate at a time (`parallel.search_n_jobs` = 1). Cell files (`cells/*.json`, `fold_scores.csv`, `cv_summary.json`) are internal research files, not contracts | Paired tests need provably identical folds; parallel model fits with sequential search keep memory to one resampled fold; contracts stay unchanged until `evaluate_test.py` writes `comparison.json` | Parallel search (`n_jobs=-1` on the search; memory blow-up with SMOTE on raw data); different folds per cell (breaks pairing); adding the cell files to `contracts.py` now |
| 2026-10-24 | In cell records, `best_params` stores technique F's `{0: 1, 1: w}` class weight as the scalar `w`, and `chosen_ratio` for `"balanced"` is 1.0 (equal weighted class mass); quick-mode `train_fraction` applies only to `--source raw` | `ComparisonRecord.best_params` is `{str: scalar}`; `"balanced"` gives fraud weight `legit / fraud`, i.e. the same mass as a 1:1 resampler; the synthetic sample is already small | Store dicts (breaks the scalar contract later); `chosen_ratio = null` for `"balanced"` |
| 2026-10-24 | Test evaluation (Prompt 09): `scripts/evaluate_test.py` rebuilds the split, refuses to run unless the training-set hash equals `run_meta.json` and every cell, records each opening in `artifacts/results/TEST_SET_OPENED.json`, and refuses a second opening without `--rerun-reason` (appended here automatically). Thresholds are read from the cell files, never recomputed. Sample runs are exempt and write to `artifacts/results/sample_test_eval/` | Makes re-opening the test set a deliberate, logged act; a changed split would leak training rows into the test set | Trust the operator; a per-cell lock |
| 2026-10-24 | Test metrics at `threshold_f2` go to the uncontracted `test_eval_details.json`; `ComparisonRecord` (contract 1.2) is unchanged | The contract has `test_at_0_5` and `test_at_tuned` (F1) only and forbids extra fields; adding `test_at_f2` would be a contract change needing team agreement | Add optional `test_at_f2` (contract 1.3) |
| 2026-10-24 | The temporal-split check (`scripts/run_temporal_check.py`) is a labelled sensitivity analysis: it clones each cell's CV-chosen pipeline, refits on the earlier 70% by `Time` and scores the rest at 0.5 and the stored F1 threshold. Because its parts contain locked test rows, on raw data it runs only after the test evaluation and is logged in the guard file | The guide asks for it (Part 5), but it reads test rows outside `evaluate_test.py`; ordering it after the single evaluation means nothing can be tuned on it | Skip the check; re-tune on the temporal split (more compute, a second protocol) |
| 2026-10-24 | Contract 1.3 (additive): `PairwiseTest` gains optional `n_pairs`, `median_difference`, `wins`, `ties`, `losses` (validated to sum to `n_pairs`); `StatsResult` gains optional `dataset_source` and `notes`. For the Wilcoxon test, `difference` is the mean per-fold difference | Prompt 10 asks stats.json to report median differences, wins/ties/losses and a note that fold scores are not independent; the 1.2 contract forbids extra fields. Purely additive, so 1.2 files still validate | An uncontracted `stats_details.json`; put the note only in findings.md |
| 2026-10-24 | Statistics (Prompt 10, `scripts/run_stats.py`): per model, two-sided Wilcoxon signed-rank (zero differences dropped; all-zero gives statistic 0, p = 1) of each technique vs baseline on repeated-CV PR-AUC paired by (repeat, fold), Holm over the 5 tests of that model; Friedman with tie correction (blocks = folds) and Nemenyi CD `q_alpha sqrt(k(k+1)/(6N))`; plus a pooled `"all"` Friedman over model x fold blocks. `alpha` is `stats.alpha` in experiment.yaml. Sample outputs go to `artifacts/results/sample_test_eval/` and `artifacts/figures/sample/`; `docs/findings.md` is written only for the raw source, and its "Interpretation (written by the team)" section is preserved on re-runs | Matches master guide Part 6; Holm per model keeps each model's family of 5 comparisons; separate sample folders stop synthetic numbers overwriting the report's | Holm over all 15 tests; Bonferroni; one shared figure folder |
| 2026-10-24 | Contract 1.4 (additive): `ManifestEntry` gains optional `model_label`, `technique_label`, `default_threshold` (`"f1"` \| `"f2"`, default `"f1"`), and `calibrator_file` + `calibrator_sha256` (set together, only when `has_calibrator`) | Prompt 11 asks the manifest to carry labels, the default threshold (= F1) and the calibrator file; 1.3 forbids extra fields and gave the backend no way to find or checksum a calibrator. Purely additive, so 1.3 files still validate | Backend derives labels and calibrator paths by naming convention; a separate uncontracted deploy file |
| 2026-10-24 | Export (Prompt 11, `scripts/export_artifacts.py`): deploy `deploy.cells` (6 LightGBM + `logreg__<technique>`, the default cell's technique); the default cell is the team's choice (`--default-cell` or `deploy.default_cell`), never automatic. Pipelines are deployed unchanged (sampler steps are inert at predict time), so each is the exact object `evaluate_test.py` scored (checked against `pipeline_sha256`); isotonic calibrators are fitted on each cell's out-of-fold training scores. `feature_reference.json` is an internal file of `fraudstudy.explain` (like the cell files), from training rows only. Presets and `demo_batch.csv` are test rows picked with the default cell's scores after the test evaluation; on raw each export is recorded in the guard (`export_presets`) and a repeat needs `--rerun-reason`. The demo batch has 25 frauds in 500 rows (5% vs 0.17%), so its precision is optimistic. Sample exports go to `artifacts/models/sample/` and `artifacts/demo/sample/` | Serves predictions from the evaluated models only; presets read test rows outside `evaluate_test.py`, so they follow the temporal check's rule; a true-prevalence batch of 500 rows would hold about one fraud | Strip sampler steps (a different file than the one evaluated); pick presets from training rows (not "unseen" payments); true-prevalence batch |
| 2026-10-24 | Explanations: logreg contribution `coef_j (x_scaled_j - mean_scaled_j)` (method `"linear"`), LightGBM `pred_contrib` (method `"TreeSHAP"`, no `shap` dependency), both in log-odds and exactly additive. `feature` is the model feature (e.g. `log1p_Amount`, keeping the visible `log1p_` name), `value` the raw input value (e.g. the Amount) and `legit_percentile` its percentile among legitimate training rows (101 raw-unit quantiles, ties take the middle of the tied run) | Master guide Part 7: exact decompositions, honest "how unusual" wording; the raw value is what a user can read and edit | Name items by raw column (`Amount`); report `log1p(Amount)` as the value; KernelSHAP |
