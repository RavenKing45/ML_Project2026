# Architectural and scientific decisions

Changes to any row require team agreement; add a new row rather than editing history.

| date | decision | reason | alternatives |
|------|----------|--------|--------------|
| 2026-10-24 | All resampling runs inside `imblearn.pipeline.Pipeline`, only during `fit`, after the train/test split | Resampling before splitting or outside CV folds leaks synthetic/duplicated minority points into validation data and inflates scores | Resample the full dataset up front (leaky); manual per-fold resampling (error-prone) |
| 2026-10-24 | Primary metric is average precision (PR-AUC) | With ~0.17% positives, accuracy and ROC-AUC are dominated by the majority class; PR-AUC reflects performance on the fraud class | Accuracy; ROC-AUC; F1 at a fixed threshold |
| 2026-10-24 | 70/30 stratified train/test split (`test_size: 0.30`, seed from config) | Keeps enough fraud cases (~150) in the test set for stable estimates while preserving class ratio | Time-based split; 80/20 split; nested CV only |
| 2026-10-24 | Raw `Time` excluded from model features | It is seconds since the first transaction in a 2-day window, so it encodes collection order rather than a generalisable signal | Keep raw `Time`; derive hour-of-day (optional side test only, `use_hour_feature`) |
| 2026-10-24 | Outliers are kept | Fraud cases are often extreme values; removing outliers would remove signal and change the class distribution | IQR / z-score outlier removal |
| 2026-10-24 | `RobustScaler` for scaling, fitted inside the pipeline | `Amount` is heavy-tailed; median/IQR scaling is less sensitive to extreme values than mean/std | `StandardScaler`; `MinMaxScaler`; no scaling |
| 2026-10-24 | Shared ratio grid and equal tuning budget for every technique | A fair comparison requires that no technique gets more search effort or a better-tuned ratio range | Per-technique grids; untuned defaults |
| 2026-10-24 | Test set evaluated exactly once, by `scripts/evaluate_test.py` | Any repeated use of the test set for tuning, thresholds or model choice biases the final estimate | Hold-out validation reused as test; repeated test peeking |
| 2026-10-24 | Models: logistic regression, random forest, LightGBM | Covers a linear model, a bagged tree ensemble and a boosted tree ensemble, which respond differently to resampling and class weights | Add SVM / neural networks (cost, limited added insight); single model only |
| 2026-10-24 | Contract 1.1: `EdaSummary` gains optional `imbalance_ratio`, `class_counts_dedup`, `amount_summary` (raw and log1p, with skewness), `time_span_hours`, `effect_sizes` (Cohen's d, sorted by abs(d)), `feature_histograms` (20 shared bins, per-class fractions) and `hour_of_day` (with the midnight assumption stated); `training_counts` defaults to `[]` | Prompt 04 needs these facts for the report and dashboard; EDA cannot fill `training_counts` because it needs tuned ratios. Purely additive, so 1.0 files still validate | Keep 1.0 and write extras to a separate uncontracted file; rename/replace KS with Cohen's d (breaking) |
| 2026-10-24 | Preprocessor output columns are `V1..V28, log1p_Amount` (29); with `use_hour_feature`, raw `Time` is replaced by `hour_sin, hour_cos` (31). Each branch starts with a median imputer; the hour columns are not scaled | `log1p_` makes the transform visible in coefficients and explanations; sin/cos already lie in [-1, 1]. The hour variant has 31 columns (28 + 1 + 2), not 30 | Keep the name `Amount`; a single hour column (loses the 23:00/00:00 adjacency); scale sin/cos too |
| 2026-10-24 | A ratio is only used if it is `> base_ratio x 1.05` (base = training frauds / legit); dropped ratios are logged and recorded in `resampling_audit.json`. The same filter applies to every technique, including F | imblearn rejects targets at or below the current ratio; the 5% margin covers CV folds whose fraud share is slightly higher. On the real data (base 0.00167) nothing is dropped; on the synthetic sample (base 0.015) 0.005 and 0.01 are | Clip ratios to the base; per-technique filtering |
| 2026-10-24 | Technique F's weight is `{0: 1, 1: r / base_ratio}` (`class_weight`, logreg / random forest; plus `"balanced"`) or `scale_pos_weight = r / base_ratio` (LightGBM), passed via `technique_params={"fraud_weight": w}`; `model_params` may not set the class weight for any technique | sklearn's `class_weight` takes a dict or `"balanced"`, not a bare float; keeping the weight inside technique F stops it leaking into other techniques' cells | Bare float weights (rejected by sklearn); weighting the legit class instead |
| 2026-10-24 | Contract 1.2: `ResamplingAudit` gains optional `base_ratio`, `dropped_ratios`; `ResamplingAuditEntry` gains optional `smote_ratio`, `fraud_weight`, `fraud_unique_after`, `fraud_duplicates_after`. The audit is written per CV training fold of the training split (fits the existing per-fold shape) | Prompt 06 asks for unique / duplicate fraud counts and a per-ratio audit; E needs both a and b. Purely additive, so 1.1 files still validate | A second, uncontracted audit file; replace the per-fold shape with a per-ratio one (breaking) |
